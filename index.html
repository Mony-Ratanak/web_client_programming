Before We Start

The Bridge: Your CSS Skills Meet WordPress

You already know CSS from Weeks 3–5. Today you use those exact same skills inside WordPress. The only difference: the class names are generated by the theme, so you have to discover them first using browser DevTools.

Weeks 3–5: Raw HTML/CSS

  • You edited .css files directly
  • Class names were your own choices
  • Changes visible immediately on save
→

Today: WordPress CSS

  • Theme generates its own class names in PHP
  • You discover those names with DevTools
  • Overrides go in the Additional CSS panel
→

The Workflow

  1. Inspect → find class name
  2. Test in browser DevTools
  3. Write rule in Additional CSS
  4. Add !important if needed
💡 Key insight: The CSS syntax — selector { property: value; } — is identical to what you learned in Weeks 3–5. The only new skill is using DevTools to discover what class names WordPress assigned.

Understanding Browser DevTools

Every modern browser has a built-in developer tool. It lets you see the HTML structure and CSS rules of any live webpage — and even edit them temporarily to test your ideas before writing permanent code.

⚠️ Temporary changes only! Everything you edit in DevTools disappears when you refresh the page. DevTools is a visual scratchpad — you use it to find the right class name and test that your CSS works, then you copy the final rule into Additional CSS (Phase 2) to make it permanent.

The CSS Cascade: Why Additional CSS Always Wins

WordPress loads CSS files in a specific order. Whichever rule loads last wins (when both rules have equal specificity). Additional CSS loads last — so it beats the theme by default.

Without !important

.entry-title a {
  color: #ff5722;
}

Works most of the time — Additional CSS loads last, so this wins.

With !important

.entry-title a {
  color: #ff5722
        !important;
}

Nuclear option — forces this rule to win against everything, even inline styles.

💡 When to use !important: Try writing your CSS without !important first. Only add it if the style doesn't apply — some themes use very specific selectors that beat normal rules. Overusing !important makes future debugging much harder.

The display:none Technique

Many WordPress themes add a "Powered by WordPress" credit or theme attribution in the footer. You can't edit the theme files directly, but you can make any element invisible with one CSS property: display: none.

display: none →

display: none

Element is completely removed from the layout. Takes up zero space. The page renders as if the element doesn't exist.

Box 1
Box 2 (display:none)
Box 3

Result: Box 1 · Box 3 (Box 2 is gone)

visibility: hidden

Element is invisible but still occupies its space. Leaves a blank gap where the element would have been.

Box 1
Box 2 (visibility:hidden)
Box 3

Result: Box 1 · (blank space) · Box 3

💡 Developer tip: display: none hides an element but does NOT delete it. If you open DevTools, you can still see it in the HTML. This is intentional — it means you can always undo it by removing the CSS rule.

Mobile Check

Custom CSS can sometimes break the mobile layout. Always test before publishing to real users.

💡 If your CSS breaks mobile: Wrap the rule in a media query to apply it only on wider screens: 
/* Only on desktop (768px+) */
@media (min-width: 768px) {
    .entry-title a {
        font-size: 2.5rem;
    }
}

Key Concepts — Quick Reference

🔍

Inspect Element

Right-click any page element to find its CSS class name in the DevTools HTML panel.

⌨

Additional CSS

Appearance → Customize → scroll to bottom. Permanent CSS overrides that load after all theme CSS.

⬇

CSS Cascade

Later rules beat earlier ones (equal specificity). Additional CSS loads last, so it wins by default.

!

!important

Forces a rule to win against all other rules. Use only when normal rules don't work.

👁

display:none

Hides an element completely — removes it from the layout but keeps it in the HTML.

📱

Mobile Check

Use the phone icon in the Customizer to verify CSS looks correct at mobile widths too.
